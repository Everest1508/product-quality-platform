{% comment %} The approver's decision dialog: one modal for the whole page, fed by a JSON payload the view builds (`decision_items`). Why one shared dialog rather than a form per row: the split controls, the date fields and the note are the same eleven inputs every time, and a queue of a hundred pending requests would otherwise ship a hundred copies of them. The per-row button only sets `current` and flips `open`. `auto` and `manual` are the two ways to answer "paid or unpaid". Auto shows the server's arithmetic and is the default; manual is for the case where the approver knows something the policy cannot know. The manual boxes are only enabled in manual mode -- a disabled box that still submits is how a request ends up with two different splits depending on which control was touched. {% endcomment %} {% load leave_tags %} {% if decision_items %} {% leave_decision_payload decision_items "leave-decision-data" %}
