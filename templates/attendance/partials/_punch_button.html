Rendered from `MyAttendanceView` on a page load and `AttendancePunchView` on an htmx punch, both through `_punch_context`, so the two cannot disagree about the state of the day. After a punch the server re-renders this partial, so the DOM is never stale; Alpine only ticks the clock and counter between requests. Markup rules the tests rely on, so keep them: * the counter is `x-text="elapsed"` and the server renders its first value as "2h 03m", so the box is not blank before Alpine boots; * `Shift HH:MM–HH:MM` appears in every state; * lateness comes from `_late_note.html`, which quotes `late_penalty_for`, the same call the payslip uses; * nothing here is `aria-live` except the punch result: a counter that changes every second would interrupt a screen reader forever. The Alpine object is plain JS in an attribute. The since/end values are integers (epoch milliseconds) from the view, never an ISO string pasted in unquoted. {% endcomment %}
